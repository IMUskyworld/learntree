# ADR-0003：AI 可选，且只做「分解节点」这一件事

- 状态：已接受（2026-09-23）
- 相关：`DEVELOPMENT.md` §2 / §9 / §20-3 / §20-7

## 背景

「AI 学习平台」最容易写成"接个大模型，什么都能问"。但本项目的主结构是问题树，
树要长出来只需要一种能力：**把一个节点拆成若干更小的问题**。讲解、出题、诊断卡点
都不改变树的结构，属于另一类需求。

同时，接了 AI 就带来三个问题：没密钥的人怎么用？模型乱答怎么办？密钥算谁的？

## 决策

1. **MVP 的 AI 只有 `decompose`**：输入是学习目标 + 从根到当前节点的路径 + 当前节点 +
   已有子节点标题；输出严格 JSON `{"subproblems":[{"title","hint"}]}`，3–6 条。
2. **AI 完全可选**：`settings.llm.enabled` 默认 `false`；未启用时 `callLlm` 一个请求都不发，
   直接返回 `not_configured` 并给出下一步指引；界面上按钮置灰 + tooltip 说明去哪开。
   不配密钥时，建树/改状态/进度/折叠/搜索/导入导出全部可用。
3. **采纳前必须人过一遍**：模型给的东西先进预览弹窗，逐条勾选、标题就地可改，
   确认后才写进树。取消则树一字不动。
4. **失败要显式**（这条是从 faillab 的教训搬过来的）：
   - 解析不出 JSON → `invalid_json` + 原文片段；
   - 模型返回空数组、或给的全是和已有子节点重复的条目 → `empty_result`，
     **绝不把"没结果"当成"这个节点不需要拆"**；
   - HTTP 非 2xx → `http_status`；超时 → `timeout`；发不出去 → `network`。
   所有失败路径都不修改树。
5. **密钥只属于这台浏览器**：只写进 localStorage 和 `Authorization` 头；
   不进 prompt、不进日志、不进默认导出、不进 `verify_mvp` 的输出。
   设置页有个"将要发送的内容"预览，密钥在那里是打码的。

## 为什么不做流式、不做多轮

`decompose` 是一次性的结构化输出，用户要读的是"拆得对不对"，不是"生成得快不快"。
流式会把预览弹窗变成一个不断变化的列表，反而更难判断。多轮对话则是另一个产品。

## 浏览器直连与 CORS

浏览器 fetch 第三方 OpenAI 兼容端点需要对端开 CORS，多数厂商不开。两条出路：

- 端点本身支持（如自建网关、部分国内兼容服务）→ 直接填地址；
- 不支持 → `scripts/llm_proxy.py` 在你本机收一圈再转发（密钥只在内存里过一遍，日志只记状态码）。

`verify_mvp.py` 会真起假服务 + 真起代理，把两条路都跑一遍（§20-6 / 20-6b），全程不碰外网。

## 后果

- 好处：没有密钥也能完整使用；AI 出问题（超时/乱答/欠费）不会污染数据；
  验收不依赖任何外部服务；换模型厂商只改三个字段；
- 代价：MVP 看起来"AI 含量不高"。这是刻意的 —— 树是主体，AI 是加速器；
- 假 LLM 只能证明协议通，**不能证明拆解质量**，这条写在 README 和 §24.5 里。
