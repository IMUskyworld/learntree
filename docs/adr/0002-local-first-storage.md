# ADR-0002：本地优先存储（localStorage + JSON 导入导出）

- 状态：已接受（2026-09-23）
- 相关：`DEVELOPMENT.md` §7 / §8.3 / §15 / §20-4 / §20-9

## 背景

学习笔记是长期资产。一个纯静态站点如果默认把数据放服务端，就需要账号、备份、隐私政策
和一整套后端；而本项目的 MVP 明确不做这些。另一面：纯 localStorage 有被浏览器清理掉的真实风险。

## 决策

**数据默认只存在浏览器本地，但导出/导入是一等公民。**

- 存储键 `learntree.library.v1`，值是自描述的 Library 对象；
- 任何改树操作 → 改内存 → 全量重绘 → 防抖 200ms 写盘；破坏性操作（删除、导入替换）立即写；
- 导出文件自描述：`{app:"learntree", schemaVersion:1, exportedAt, treeCount, library}`；
  导入时这四个字段缺一个就**拒收并逐条报路径**，不猜未知格式；
- 合并导入只在树 id 真冲突时重发 id；同名不同 id 就是两棵树（不去猜哪棵是"同一份"）；
- 默认导出**剥掉 API key**，只有显式要求才带，并在界面上标红警告。

## 三条硬规则（都被测试钉住）

1. **读坏了不写盘**。JSON 语法错、结构不合法、版本号比当前新 —— 一律返回空库继续工作，
   但绝不覆盖原内容，并明确告诉用户"原内容未覆盖"（§20-4）。
   理由：用户可能还能修；悄悄清空是更坏的结果。
2. **版本只认 1**。不做"猜测式迁移"：`schemaVersion` 不匹配就是拒绝，
   将来要迁移就写显式的 `migrate()`，而不是让 normalize 函数顺手改语义。
3. **不合法就拒写**。`saveLibrary()` 先跑 `validateLibrary()`，不合法的库根本写不进去，
   避免把一个损坏的内存状态固化到磁盘。

## 后果

- 换浏览器 = 数据看不见（不是丢了，是存在另一个 origin 下）。README 里写清楚用导出/导入搬家；
- 无痕模式下关窗即失 —— 无法检测也无法救，只能在设置页提示；
- 没有协作、没有多端同步；这是有意的：MVP 不做服务端；
- 隐私模式或禁用存储时 `browserBackend()` 探测失败返回 `null`，界面降级为"本次会话内存可用 +
  提示你必须导出"，而不是崩溃。

## 备选方案

- **IndexedDB**：容量大，但 API 异步、代码量翻倍，MVP 的树（几十 KB）用不到；
- **File System Access API**：能直接写用户磁盘上的 `.json`，最贴近"本地优先"，
  但只有 Chromium 支持且权限模型复杂，留给 M2；
- **后端 + 账号**：与"零服务端、零依赖"的形态冲突。
