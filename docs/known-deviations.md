# 已知偏差与诚实清单

规范是 `DEVELOPMENT.md`，这里是"实际做出来的东西和它不一样的地方"，以及为什么。
逐条核验表在 `DEVELOPMENT.md` §24.1，本文不重复证据，只讲取舍。

## 与规格书的偏差

| # | 偏差 | 原因 | 影响 |
| --- | --- | --- | --- |
| 1 | §20-11（浏览器端到端）在 `verify_mvp.py` 里永远是 SKIP | 验收脚本不自动开浏览器，也不拿别的手段冒充它 | 证据在 §24.6 的手工实测记录里；CI 上这一条不会变绿，是设计如此 |
| 2 | §14 的"首屏 < 300ms 可交互"没测 | 测它要引入 Lighthouse/devtools 工具链，违背零依赖 | 只测了 core 层的算法耗时（远低于软目标） |
| 3 | 多了一条 §20 里没有的检查项 20-6b（CORS 代理） | 代理是"真模型能不能用"的前提，不验等于没交付 | 只增加检查，不放松任何一条 |
| 4 | 「移动父节点」用弹窗列表而不是右键菜单 | 深树上列表更好点，也省掉一套菜单组件 | 交互与 §11 描述的形状不同，功能等价 |
| 5 | `index.html` 里的模块脚本是运行时注入的 | `file://` 下必须"根本不去加载"，静态 `<script type=module>` 做不到 | §20-8 的静态断言按这个形状写；不影响 http 访问 |
| 6 | 节点文字折行宽度按字符数而不是像素测量 | 零依赖下没有 `measureText` 的可靠同步路径（SVG 未挂载时不可用） | 中英混排时右侧留白不均，但不会溢出节点盒（实测调参：标题 12 字 / 提示 17 字 / 节点宽 244px） |

## 产品上的已知局限

1. **AI 拆解质量只抽测过一轮真模型**。2026-10-18 用 DeepSeek（deepseek-chat）经本地代理实测，
   三段链路与浏览器全流程全部可用（`DEVELOPMENT.md` §24.7）；但样本很小，其它厂商/模型未验证。
   更早的证据全部来自本机假服务 —— 它只能证明"协议通、解析对、失败不装成功"，不能证明拆得好。
2. 布局是"叶子占行 + 父节点取中点"的朴素算法：同层子节点很多时树会很高，
   没有做边交叉最小化，也没有做水平紧凑。
3. **只有一次性撤销**：删除节点 / 删除树 / 整库导入前会存一份快照，其它操作没有 undo。
4. 没有移动端适配调优：<900px 只保证"堆叠可用不崩"，触控目标偏小。
5. 搜索只匹配标题与备注的子串，不做拼音、模糊、语义。
6. 折叠状态会随导出文件一起走（视图状态混在数据里）—— 有意为之，但确实是取舍。
7. 没有 PWA / Service Worker：断网时静态资源本身能缓存，但应用不会离线安装。
8. 无痕模式下 localStorage 关窗即失，应用无法检测也无法挽救，只能靠导出。

## 实现上刻意"做重"的地方

- **导入只认自描述文件**：缺 `app` / `schemaVersion` / `exportedAt` / `library` 任一项就拒收，
  逐条报路径。宁可让用户导出重来，也不猜格式把数据搅浑。
- **读坏了不写盘**：本地存储损坏时按空库打开，但原内容一动不动，并说明"未覆盖"。
- **模型返回空列表 = 失败**：`empty_result` 是错误码而不是"这个节点不需要拆"的结论
  （从 faillab 的"命令没跑起来 ≠ 已修复"搬来的三态判定）。
- **`innerHTML` 全项目恰好 1 处**，且必须带 `innerHTML-ok` 标记，由验收脚本强制计数。
